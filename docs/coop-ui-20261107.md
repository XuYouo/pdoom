# 在线双人合作界面与交互验收 · 2026-11-07

协议与运行时说明见 [合作架构](coop-architecture.md)。本记录覆盖 React 大厅、独立合作游戏壳、双人状态、暂停设置与退出交互。React 只订阅控制消息及 5Hz 展示快照；玩家输入与高频世界传输由游戏运行时处理。

## 已实现行为

- 大厅使用现有账户登录与服务器认证。创建、加入、准备和开始均等待真实服务器状态；邀请码为 8 位字母或数字 2–9，输入会统一大小写，复制失败时选中可手动复制。房间只展示协议提供的席位与连接状态，不把客户端缓存名称当作服务器确认身份。
- 创建或加入期间可以取消；已发出的请求等待原响应后再离房。10 秒未确认会明确提示结果未知并阻止重复提交，允许明确断开；界面说明席位可能继续保留最多 30 秒。正常退出等待服务器离房确认，不仅关闭 WebSocket。
- 合作游戏使用独立 `GameBridge` / `GameCanvas`。引擎加载完成时重新检查当前房间与对局身份，已关闭的旧对局不会被迟到的 `ready` 事件重新启动。单人存档和单人排行榜不参与合作结算。
- 两名玩家有独立完整度、倒地状态、真实救援进度和继续准备状态；HUD 展示共享 Doom、TOK、得分与模拟时间。Leviathan 吞掉完整度 UI 时，双方当前 HP 数字和进度条均隐藏，暂停摘要不绕过这项规则。
- 任一玩家可暂停，只有在线且双方连接恢复后的房主可恢复。断线提示保留席位最多 30 秒，重新连接不会自动恢复战斗。暂停可使用原有声音、动态效果与全屏设置；关闭设置仍停在暂停界面。
- 合作休息室由房主交易和排序，共享资源与构筑。修补目标明确选为 1P 或 2P，房主满血时仍可为受损队友购买修补。客机只读，且不把自己的修补预览误称为房主所选目标。交易会清除继续准备，双方必须重新准备。
- 奖励劫持复用已确认的实际 Doom 预览与取消优先确认框。合作休息室只说明本场运行状态，不承诺自动保存到单人检查点。失败可双方准备后从当前合作安全点重试，章节突破展示五章路线和下一章，最终团队战报不提供单人分数上传。
- 退出立即停止本机模拟，再等待离房确认；请求失败或超时保留可见反馈与重试/明确断开操作。

## 修复过的真实问题

1. 合作壳改为同一个 `main.game-shell.coop-play` 后，旧祖孙选择器不再匹配。已统一修正命中关系；桌面实看任务、状态与操作区分离。
2. 原单人窄屏样式隐藏 `.game-actions`，会把合作暂停与全屏一并隐藏。合作操作区明确保留 flex 显示，并通过真实 390 宽浏览器检查。
3. 首轮两种屏幕均发现原生设置弹窗的 Tab 到末尾时，焦点会离开弹窗。通用 `Dialog` 现仅在当前弹窗首尾接管 Tab，过滤隐藏/禁用控件、关闭的 disclosure 内容、负 tabindex 和同组非选中 radio；方向键仍由浏览器处理，嵌套父层不拦截。原断言保留，修复后两项完整通过。

首轮失败证据保存在 `artifacts/ui-workbench-20261107/coop-ui-pass1/`，未覆盖；最终证据在 `coop-ui-pass2/`。
