# 前端与交互打磨 · 2026-11-06

依据 `GAME_DESIGN_GDD.md` 的暖橘终端、Clawd三态与风险交换机制，以及 `架构与开发规范参考.md` 的页面就近组织、UI=f(state)、React/Phaser边界实施。

## 本次变化

- 主菜单以原生Clawd图集作为角色展示，提供对齐 / 面具 / FOOM预览；使用现有32px帧整数倍放大，不新画或替换Aseprite源。切换明确标为预览，不发送游戏命令、不修改存档。续玩入口展示真实章节、生命和Doom。
- 主按钮增加按压、箭头反馈与短入场过渡，支持系统和本机减少动态效果。桌面采用角色与标题双区域；竖屏自然滚动，短横屏保持操作区可访问。
- HUD从低频快照派生Doom形态、50/80刻度、低生命配色、E透视状态与上下文满载提示。形态使用现有`doomForm`，严格保持`>50`和`>80`边界；Leviathan吞生命读数及FOOM终局分支保留。
- 操作手册先展示六组按键，再展示本章战术；回溯、构筑、捐款、检查点和终章规则收进原生details。删除玩家无需理解的接口和运行时术语。
- 修复点击Q/E/R后按钮焦点吞掉后续游戏按键的问题。鼠标点击回画布，键盘激活保留可遍历的控件焦点；控件上的Enter/Space不触发射击或跳跃。
- 弹窗在React移除DOM前关闭，恢复浏览器原生焦点；主菜单只在初次就绪时设默认焦点，嵌套指南关闭后仍暂停。

## 结构与边界

展示在`pages/GamePage/components`，输入边界在页面`functions/hudInput.ts`。新增CSS显式在基础game-shell之后导入，未调整旧休息室/结局样式的导入顺序。通用Dialog只调整DOM生命周期。

本轮未修改Scala API、存档schema、物理、战斗规则或逐帧模拟；没有引入React逐帧状态或新资产依赖。已有未提交工作保留。
